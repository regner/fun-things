# S02 — desktop camera and foot-control exploration

7 October 2026. **Desktop candidate, not S02 acceptance.** Codex owns this bounded
fixture; Regner owns feel/product ratification. Initial experiment cap: 1–2 focused
days. This pass built one corner/alley harness, not production gameplay. The
[ratified brief](../design.md), [art direction](../art-direction.md),
[world layout](../world-layout.md) and [S01 route](s01.md) remain authoritative.

Question: can facing-relative foot controls, a fixed-yaw vertically downward
perspective camera and mixed-height buildings yield a readable desktop starting
point? Alternatives are camera FOV candidates, not a substitute movement model.
No twin-stick, world-relative WASD, independent mouse aim, camera rotation or zoom
control was introduced.

## Ownership and outcome validation

Input collection (`desktop_input.gd`), motion (`actor_motion.gd`), bounded query
(`aim_probe.gd`) and presentation (`camera_rig`, `building_view`, `probe_overlay`)
are separate. `fixture.gd` orders the standalone step. It introduces no client
outcome authority, replication or prediction. Future authoritative/predicted motion
must reuse equivalent rules; S03-R owns that decision. Saved scenes own all node
composition, UI layout, collision and placement; only dynamic actor/camera state
moves at runtime. The 2D marker/trace is a diagnostic overlay, not a 3D generated mesh.

`tools/s02/run.py` copies the saved project into an isolated profile, removes only
development autoload/editor plugins in that copy, imports fresh, checks actual
production APIs and compares persisted resource hashes. It checks forward/reverse
distance, turn-without-strafe, facing-relative movement, wall stop, passage/corner
traversal, clear hit, blocked hit, close-wall muzzle obstruction, bounded firing,
nonfinite intent, routed physical-key mapping, cancellation, camera axes, source
sockets, building heights, source links and UID/path agreement. Runtime logs and
exit status both matter. This is not a network, packaged export or full-plugin proof.

Observed wall stop: (6,0.001,0.38021); corner traversal ends approximately
(3,0.001,-9). Forward travels5 m in one second; reverse3 m. An independent live MCP
physical-W trial moved1.25 m in250 ms; this is submitted-input behavior, not a human
latency/feel measurement. Query hit the clear target and world blocked the hidden
one. Re-running after the cutaway preserved collision/query outcomes.

Input API checks pass for focus cancellation, no held echo on regain and local-menu
cancellation. The [final native-window run](s02-evidence/os-focus.log) also observed
actual minimize/focus loss: movement stopped at(0,0.001,3.499997), shots remained2,
and restore regained focus with neutral input. Held keys were injected through the
saved window; minimize/restore came from the OS. This proves that bounded desktop
notification path, not physical-key Alt-Tab or suspend/resume behavior.

Earlier attempts on this KDE Wayland desktop reported a window as simultaneously
minimized and focused; their [failed log](s02-evidence/history/os-focus-unproved.log)
is retained separately. The earlier X11 driver failed to acquire window focus before
injecting keys and was removed. The saved `focus_runner.tscn` fails if no held
movement or real focus transition occurs. Human physical-key/focus playtesting is
still pending; API checks and this automated minimize case do not certify every OS
focus path or the handheld targets.

## Tools, authoring and reproducibility

Engine4.8.dev7.official.c971f93e7, gdstyle0.3.0, Godot MCP Toolkit1.0.3;
Blender5.2.2 LTS d13f752e3b9c / glTF5.2.40. Pins and vendor addons are unchanged.
No existing Godot/Blender process was found at start. The pinned editor was launched
with approved host display/socket access on this worktree and reported NO_SCENE.
Godot MCP authored all scripts, scenes, resources and project input/viewport settings;
saved scene state and diffs were inspected. Additional discovered tools were absent
from the callable surface and the toolkit rejects GLB instantiation, so the S02
editor bridge reuses S01's editor-only linked-import/resource/scene operations.

Blender MCP was unavailable. An owned GUI launch never opened its listener; only
that process was stopped. Isolated Blender CLI authored the committed .blend and
explicit exports. The first source-save run reported sandbox audio/thumbnail/cache
errors; the source was saved. Subsequent exports used private writable config/cache
paths. The known optional MeshOptimizer-library diagnostic is retained; GLBs contain
no compression extensions/images. All nine final exports are byte-identical on
reexport. No separate unsaved Blender scene was touched. The initial bootstrap process hung
after the confirmed save and was stopped by PID after identifying its worktree;
subsequent isolated reexports completed normally.

The live editor refreshed external models and explicitly closed/reopened/saved all
affected wrappers, fixture and inherited scene. First reopen normalized redundant
instance type fields and inherited UI defaults while preserving node/UID identities;
a subsequent roundtrip preserved all eleven saved scene files byte-for-byte. A headless import is not treated as
synchronizing that editor. Known toolkit progress-dialog/message-queue diagnostics
and transient compile errors during sequential authoring are retained in logs;
final compilation is a separate explicit all-owned-script run.
