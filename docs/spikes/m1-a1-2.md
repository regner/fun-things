# M1-A1.2 — ENet transport and menu host/join flow

10 October 2026. This production row adds the initial ENet provider behind M1-A1.1's
`SessionTransport` seam. It stops at an admitted `ACTIVE` session; Match/world loading and gameplay
replication remain owned by later rows.

## Production boundary

`ENetTransport` owns bounded address/port parsing, four-channel capability facts, native ENet peer
creation and connection callbacks. A listen server applies `bandwidth_limit(0, 0)` immediately after
`create_server` and before `peer_ready`, preserving the pinned c971 workaround. Boot saves the
transport below `/root/Boot/Session`, registers it before accepting menu work, and routes Host and
Join forms through SessionService. Standalone still creates no network peer.

SessionService owns the protocol/content handshake at the fixed `/root/Boot/Session` endpoint.
It configures `SceneMultiplayer.auth_callback` and the bounded `auth_timeout` before publishing the
ENet peer. Requests and verdicts use `send_auth` with raw `PackedByteArray` values; each side calls
`complete_auth` only after acceptance, so unauthenticated peers cannot dispatch RPCs. Remote identity
comes from the transport peer ID supplied by `peer_authenticating`, correlated with the active
operation and per-connection token. Exact protocol mismatch returns `INCOMPATIBLE`; content,
district, topology or definition mismatch returns `CONTENT_INVALID`; and capacity exhaustion returns
`FULL`. The host slot is included in capacity. One bounded native rejection slot permits an explicit
full-session response, and native peers that do not submit the five-field handshake are removed after
the five-second handshake deadline. ENet targets expire when
the adapter closes. Boot retains the user's raw address and port so UI Retry reparses a fresh target
without exposing that text to SessionService.

The initial compatibility identity is deliberately configurable and defaults to protocol `1`, district
`brackett_island`, topology `0`, and development content/definition IDs. The reliable authentication
request uses a fixed packed-byte shape capped at 512 logical bytes. The host validates raw field
lengths and UTF-8 before allocating `StringName`, permits two requests per peer per one-second window, and
disconnects a peer after three malformed or rate-limited requests. M1-C2.1 owns the saved-world
content identity and will configure the production fingerprints through this API; this row does not
invent a second world identity.

Connection attempts have a 15-second local deadline, negotiation has five seconds, and all cancel,
failure, leave and host-loss paths detach the multiplayer peer before the existing shared five-second
close. Late provider callbacks cannot reactivate a closed operation. Host rosters use sender-derived
native peers and fresh participant IDs; disconnected peers release their rows.

## Tests and evidence

GUT coverage under `tests/unit/session/` checks endpoint validation, four distinct channels, fake
provider state/cancel/timeout/late-callback handling, protocol versus content failures and Boot menu
routing. `tools/session/run_session_flow.py` launches isolated, capped, headless production API
processes and retains command, engine and stdout logs. Its ten loopback cases cover successful
admission, client leave plus fresh-target rejoin, protocol mismatch, content mismatch, full session,
host loss, oversized byte-array/string abuse, repeated handshake rate abuse, cancel during connection
and unreachable host. The 70 KiB raw-auth case proves application rejection and then admits a normal
probe through the same surviving host. The runner rejects script/engine errors, nonzero exits and
stops only its own children.

Pinned Godot `4.8.dev7.official.c971f93e7` ClassDB inspection found the required authentication API
but no configurable receive/reassembly or native packet-size ceiling on `ENetMultiplayerPeer`,
`ENetConnection` or `ENetPacketPeer`. The 512-byte application cap is pre-Variant and pre-RPC, but
native ENet has already received and reassembled the packet before `auth_callback`. A large packet can
therefore consume native receive resources before rejection. This residual allocation/amplification
risk remains for release hardening; the transport capability reports no native receive limit rather
than asserting the 16 KiB logical stream size as one.

The Godot editor and MCP editor tools were unavailable to this worktree. The Boot scene extension and
test harness scene were edited as text, then loaded by pinned headless Godot. Script UID sidecars were
generated by the pinned editor import and committed. The focused results and exact limitations are
retained in [the evidence directory](m1-a1-2-evidence/README.md).
