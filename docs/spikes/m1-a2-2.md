# M1-A2.2 — identity, baseline and durable replication core

11 October 2026. This production row ports the accepted S11/S17 direction without loading
or copying archived fixture code. The Godot editor was unavailable; scripts and the minimal
integration harness were edited directly, imported with the pinned engine, and checked by the
canonical production entrypoint.

## Delivered core

- `ReplicationIdentity`, `PeerIdentityRegistry` and `EntityGenerationTracker` own exact session,
  sender-derived participant, entity and generation validation. SessionService remains the sole
  participant allocator; the registry mirrors its mapping and rejects retired participant reuse.
  Entity reuse advances generation.
- `MeasuredReplicationCodec` owns the frozen S11 movement and durable shapes. The island range
  disposition and absent vertical field are recorded in [the codec record](m1-a2-2-codec.md).
- `ReplicationAdmission` captures immutable current rows, bounds the 1 MiB/128-chunk baseline and
  2 MiB/4,096-record journal, sends the marker after the journal, and grants input only after the
  current sender's matching marker acknowledgement. Attempts enforce the 10-second baseline and
  5-second handoff deadlines under a 60-second total ceiling and fail independently.
  `BaselineAssembler` validates metadata, duplicate identity, bytes, cardinality
  and checksum before exposing rows.
- `ReplicaStateStore` installs a complete baseline atomically, applies contiguous global durable
  revisions, retains tombstones, rejects stale session/match/generation/tick state, and gives
  lifecycle and movement distinct writer fields. Movement uses per-entity tick watermarks, so
  alternating subsets recover independently. At most one newest future row per entity generation
  is retained under the 148-row bound; a durable gap or overflow requests resync.

The row deliberately does not edit Boot, Match, Session or player scenes while M1-A2.5 owns those
files. `ReplicationTransport` is the injection seam for that wiring. A follow-up wiring commit must:

1. add one saved `Replication` root under `Match`, initialized with Match's SessionId and revision,
   and make Match the only coordinator of authoritative capture and replica application;
2. hand SessionService's admitted `(native_peer_id, participant_id)` mapping and disconnect cleanup
   from Boot to that root without creating another participant allocator; and
3. start host baseline admission only after authoritative player spawn/binding is complete, then
   install baseline/current rows at the client player-apply boundary before opening input.

The integration test's one-byte message tags and bounded Variant metadata are test harness framing
only, not a second production codec.

## Tests and evidence

GUT coverage under `tests/unit/replication/` includes identity/generation reuse, exact codec sizes,
quantization/clamp/malformed handling, traversal of saved Brackett node origins against the 50 m
safe margin, fake-transport baseline-before-input ordering, checksum/out-of-order/duplicate chunks,
timeout, stale revisions, one-writer lifecycle fences, future-generation recovery and alternating
subset convergence.

`tests/integration/replication/run_replication.py` launches separate capped headless host and client
processes through real ENet. The host sends current baseline rows, a reliable death transition and
handoff, then grants and sends fresh movement. The client installs baseline before acknowledging,
applies durable state through the marker, and verifies movement changed pose without changing the
durable death phase. The runner wraps both Godot children in GNU `timeout`, retains external logs,
rejects engine/script diagnostics and stops only its own children.
