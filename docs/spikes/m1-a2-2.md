# M1-A2.2 — identity, baseline and durable replication core

11 October 2026. This production row ports the accepted S11/S17 direction without loading
or copying archived fixture code. The Godot editor was unavailable; scripts and the minimal
integration harness were edited directly, imported with the pinned engine, and checked by the
canonical production entrypoint.

## Delivered core

- `ReplicationIdentity`, `PeerIdentityRegistry` and `EntityGenerationTracker` own exact session,
  sender-derived participant, entity and generation validation. SessionService remains the sole
  participant allocator; the registry mirrors its mapping and rejects retired participant reuse.
  Entity reuse advances generation, and allocation plus reuse share the 65,536 spawned-reference
  ceiling for one match revision.
- `MeasuredReplicationCodec` owns the frozen S11 movement and durable shapes. The island range
  disposition and absent vertical field are recorded in [the codec record](m1-a2-2-codec.md).
- `ReplicationAdmission` captures immutable current rows, bounds the 1 MiB/128-chunk baseline and
  2 MiB/4,096-record journal, sends the marker after the journal, and grants input only after the
  current sender's matching marker acknowledgement. Attempts enforce the 10-second baseline and
  5-second handoff deadlines under a 60-second total ceiling and fail independently.
  `BaselineAssembler` validates metadata, duplicate identity, bytes, cardinality
  and checksum before exposing rows.
- `ReplicaStateStore` installs a complete baseline atomically, applies contiguous global durable
  revisions, retains tombstones, rejects stale session/match/generation/tick state, and gives
  lifecycle and movement distinct writer fields. Reliable spawn authorization advances durable
  revision independently of pose arrival; matching movement materializes the authorized entity in
  either delivery order. Movement uses per-entity tick watermarks, so alternating subsets recover
  independently. At most one newest future row per entity generation
  is retained under the 148-row bound; a durable gap or overflow requests resync.

The initial core row deliberately left Boot, Match and player wiring to M1-A2.5. After A2.5 landed,
the follow-up wiring delivered those recorded hooks:

1. saved `Match/Replication` sits beside, never inside, `World` and `Anchors`; it receives the
   SessionId/revision and owns authoritative capture plus replica application;
2. SessionService emits its admitted `(native_peer_id, participant_id)` mapping and disconnect
   cleanup to Boot, which calls down to the current Match without adding another allocator; and
3. the host allocates each player an EntityRef distinct from its Session participant identity,
   spawns it in the first free stable `PlayerSpawns` slot, delivers binding dependencies before
   state records, and opens client intent only after baseline install and handoff acknowledgement.

The host applies admitted `FootCommand` intent through `ActorMotion` and publishes one shared 20 Hz
encode of every player. The remotely callable command boundary accepts only the fixed 16-byte
`FootCommandCodec` packet, rejects size before decoding, and retains sender-derived admission,
rate, sequence and stale-input checks. Runtime host physics services admission deadlines from the
same monotonic clock used to create them; deterministic coverage expires baseline and handoff
stalls independently while an admitted peer and host actors continue. RPC configuration keeps
control and acknowledgements on channel 0, reliable match state on 1, input on 2 and movement on 3.
Clients apply the latest host pose directly, retain the A2.5 Coral Courier presentation, and do not
predict or interpolate; those improvements remain A2.3 work. Standalone continues to use
LocalRig's existing direct authority path while the saved replication root is inert.

## Tests and evidence

GUT coverage under `tests/unit/replication/` includes identity/generation reuse, exact codec sizes,
quantization/clamp/malformed handling, traversal of saved Brackett node origins against the 50 m
safe margin, fake-transport baseline-before-input ordering, checksum/out-of-order/duplicate chunks,
timeout, admitted-peer send failure isolation, stale revisions, one-writer lifecycle fences,
spawn-before-movement and movement-before-spawn recovery, the spawned-reference ceiling, and
alternating subset convergence. Wiring regressions also inject monotonic time through the runtime
coordinator, retain another admitted peer across both admission timeout phases, and inspect the
registered RPC channel configuration.

`tests/integration/replication/run_replication.py` launches separate capped headless host and client
processes through production SessionService and real ENet. Both instantiate the saved Match, the
host and remote Courier spawn at `Spawn01`/`Spawn02`, baseline and handoff complete before input,
and the client first sends malformed fixed-size and oversized packets over the actual input RPC.
The host must record both bounded rejections while its remote actor remains unchanged. Deterministic
valid intent then moves the host-authoritative remote body, and the client must observe that movement
through latest-state application. The runner wraps both Godot children in GNU
`timeout`, retains external logs and a `result.json` with child exit codes, rejects engine/script
diagnostics and stops only its own children. The post-review run at
`C:/tmp/ft/lanes/m1-a2-2/review2-enet-rebased-final/` used the pinned engine and UDP 56860. Its
`result.json` records host/client exit 0 with no diagnostics or failures. The host receipt records
one `PACKET_SIZE` and one `MALFORMED_COMMAND` rejection with no authority movement before valid
intent; both receipts report bounded-boundary proof, a loaded Match, two players and more than
0.5 m of authoritative remote movement observed locally.

The earlier lane report's ENet pass claim was invalid: review found metadata and durable dispatch
fallthrough in the checked-in harness, so that run is not acceptance evidence. After explicit
dispatch repair, a fresh pinned-engine run completed at
`C:/tmp/ft/lanes/m1-a2-2/review-fix-enet/`; its retained `result.json` records host exit 0, client
exit 0, no diagnostics, no failures and `ok: true` on UDP 56405.
