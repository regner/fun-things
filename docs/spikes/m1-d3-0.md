# M1-D3.0 — production host-budget instrumentation

11 October 2026. This row adds the ongoing production timing seam requested by decisions 14
and 22. It is a current-row tracking result, not final M1-D3 capacity acceptance.

## Delivered contract

`HostTickProfiler` records one inclusive `total` bracket and registered subsystem brackets with
`Time.get_ticks_usec()`. It is explicitly enabled, retains a fixed-capacity ring, and computes
nearest-rank median/p95/p99 outside the measured bracket. When disabled, every bracket returns
before a timer read; focused tests verify a zero timer-read receipt and zero samples.

`HostTickCoordinator` is an enclosing caller, not a second state owner. It calls the current
production owners in this order:

1. `PedestrianCore.step` for decisions and `FootCommand` emission;
2. `ActorMotion.step` for pedestrian and available player bodies; and
3. `PedestrianCore.sync_position` for the observed motion result.

The current section names are `pedestrian_decisions` and `actor_motion`. Instrumentation never
changes a gameplay result and no percentile gates tests or runtime. The run exposed one existing
boundary issue: float32 pedestrian facing could round just below `-PI`, causing `ActorMotion` to
reject an otherwise valid command. `PedestrianCore.to_foot_command` now clamps its emitted yaw to
the public `FootCommand` range after packed storage, with a 400-tick/64-agent regression.

## Repeatable tracking run

The saved test composition under `tests/performance/host_budget/` instantiates saved capsule actor
fixtures, 64 production pedestrian slots on a deterministic synthetic 8x8 graph, and four player
actors. It runs real 60 Hz physics callbacks with a 60 FPS cap. The repository runner requires the
pinned engine and GNU `timeout`, isolates writable Godot directories, rejects engine/script
warnings, writes outside the checkout, and labels observed Godot-process contention.

```sh
export PATH="$(dirname "$(mise -C C:/GameDev/git/fun-things which godot)"):$PATH"
timeout 180 python tools/host_budget_tracking.py \
  --godot "$(command -v godot)" \
  --output C:/tmp/ft/lanes/m1-d3-0/tracking \
  --warmup-ticks 600 --measured-ticks 3600
```

The retained Windows run used `4.8.dev7.official.c971f93e7`, 600 warmup ticks and 3,600 measured
ticks. Another Godot process was observed, so every timing below is labelled **contended**.

| Section | Median ms | p95 ms | p99 ms |
| --- | ---: | ---: | ---: |
| Pedestrian decisions/commands | 0.793 | 1.523 | 2.185 |
| ActorMotion plus pedestrian pose handoff | 0.319 | 0.763 | 1.329 |

The current-row total is within decision 22's soft approximately 4 ms p95 tracking target. This is
reporting only, and the result is not evidence of 1.735 ms production headroom: it is headless,
uses a synthetic graph, disables tracking-actor collision layers, and omits networking,
replication, traffic, combat, lifecycle, presentation and the Brackett world. The small machine,
contention and result receipt is
[`m1-d3-0-evidence/result.json`](m1-d3-0-evidence/result.json); full logs remain outside the
