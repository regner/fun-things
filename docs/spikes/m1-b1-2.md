# M1-B1.2 VehicleInteraction transaction matrix

10 October 2026. This production slice replaces B1.1's temporary driver-assignment seam with
`VehicleInteraction`, owned below Match. Reliable ENTER and EXIT requests derive participant identity
from the admitted RPC sender and carry exact SessionId, MatchRevision, player EntityRef, vehicle
EntityRef where applicable, and bounded action sequence fences. The host sorts accepted work by tick,
participant, then action sequence. Results report processing but never install gameplay state; reliable
vehicle descriptors remain the state writer.

Entry is host-confirmed under owner decision 23. The requester may play only the imported door-hinge
presentation for about 0.3 seconds before confirmation. Foot collision/visibility, controlled body,
camera follow, HUD context, and drive-command epoch change only after the committed descriptor. A
rejected request leaves the actor transform and ownership unchanged. Entry validates live lifecycle and
vehicle generations, vacancy, authored entry range, stopped speed, the chosen entry clearance, and
available assignment epochs. The accepted tick follows the 18-tick (~0.3 second) door presentation.

Exit requires planar speed below 0.5 m/s and searches authored left then right exit sockets. The saved
sockets retain the delivered approximately 1.5 m offset. Match applies the player clearance envelope,
spawn reservations, and physics query while excluding the seated actor and current vehicle. No clear
candidate returns `EXIT_BLOCKED` without changing the seat, control revision, actor pose, collision, or
presentation. The reliable transfer carries the exact player exit pose, applies it before reopening
presentation/input, and advances the foot-input epoch so pre-seat packets or prediction cannot replay.

Death and disconnect release a surviving car into `VehicleMotion`'s neutral coast-to-stop rule.
Destruction releases and neutralizes the car without inventing an unsafe foot pose. A seated resync
keeps occupancy but advances the command epoch and clears its held queue. Reset drops pending and
cached old-match actions before authored vehicle state is restored. Lifecycle and destruction release
still succeed at the final input epoch without wrapping it; that vehicle can no longer be reassigned.
Parked cars and late-join seat state continue to derive from the authored `PARKED_CAR` anchors and the
bounded descriptor baseline.

The matrix ports S04-T's ordering and fencing intent, but not its predicted-entry adapter or sentinel
occupant. Reliable actions use participant-scoped queues, the ratified 16/s burst-32 token bucket, a
four-action per-participant tick budget and a 4096-byte envelope limit. Production tests cover snap-free
and blocked-entry rejection, deterministic same-tick claims and queue fairness, moving/blocked/clear
exit, foot epoch/prediction fencing, seated resync, death/disconnect coast, final-epoch release,
destruction, reset invalidation, LocalRig vehicle/foot follow, and current late-join hydration.

`DesktopDriveInput` is saved in LocalRig and collects physical aliases only while a confirmed vehicle is
bound. Clients predict and submit the sampled command; listen-server input is codec-validated and
queued through the same authority owner. Exported Windows host and client acceptance uses one viewport
key press each to drive continuously for ten seconds, brakes below 0.5 m/s, exits, proves a neutral stale
foot window, then walks on fresh physical input. A mutation case disabling the client drive collector
must fail that acceptance.
