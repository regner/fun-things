# M1-A2.1 production foot command and ActorMotion

10 October 2026. This row introduces production on-foot command collection and motion. It
ports the accepted S02 world-relative movement and mouse-facing rules deliberately; production
code does not load the reference-only `prototypes/` archive.

## Implemented boundary

- `FootCommand` owns the exact local held-intent shape: positive sequence, nonnegative
  `client_tick`, normalized finite move vector, canonical aim yaw, and fire/alternate held intent.
  Its decoder rejects missing, extra, mistyped, nonfinite, and out-of-range fields before motion.
- `DesktopFootInput` tracks production InputMap actions through `_unhandled_input`, normalizes
  WASD diagonals, projects the mouse ray onto the actor plane, and clears every held physical
  alias on window/application focus loss. Focus regain remains neutral until a fresh event.
- `ActorMotion` is the one writer for foot pose, velocity, facing, and collision. Authority,
  standalone, and replay call the same typed `step`; replay has no presentation/gameplay side
  effects beyond the same optional motion-driven animation update. Fire and alternate intent are
  carried for later owning systems and do not create damage, effects, or actions here.
- `scenes/entities/player.tscn` is a `CharacterBody3D` with the accepted 0.35 m radius, 1.8 m
  capsule, Actor layer 2 / World mask 1, and the delivered Coral Courier scene linked below an
  authored presentation anchor. Presentation selects idle or directional run clips from solved
  motion state and never writes the physics body.
- `scenes/dev/foot_motion.tscn` supplies a 60-capped standalone walk/aim harness on a translated,
  source-linked Brackett ground sector. It adds no production camera/HUD contract. `scenes/dev/**`
  is excluded from every desktop export preset, and export inspection rejects accidental leaks.

`CharacterBody3D` is retained from S02 rather than the S10 selective-query path. The player needs
continuous static-world wall collision now, while S10's graph-kinematic query was evaluated for a
large host-owned pedestrian crowd. One CharacterBody adapter therefore keeps collision and shared
movement in the same production owner without adding a second player collision implementation.

## Scene and editor workflow

The Godot editor and MCP editor tools were unavailable to this lane, so the two explicitly requested
new scene hierarchies were authored as text. The pinned engine imported all new scripts to generate
UID sidecars, then loaded and packed/saved both scenes headlessly. Dependency and scene UIDs were
checked after that roundtrip. No delivered player asset or greybox source was modified.

Run the owner harness from the repository root with the pinned engine:

```sh
mise exec -- godot --path . --max-fps 60 res://scenes/dev/foot_motion.tscn
```

WASD moves in fixed world/screen axes, the mouse changes facing, left mouse carries fire intent, and
right mouse carries alternate intent. The harness intentionally stops before camera/HUD, networking,
replication, prediction history, combat outcomes, or lifecycle ownership.

## Validation and evidence

Focused GUT coverage independently checks exact decoder rejection, five-metre-per-second cardinal and
diagonal speed, instant stop, aim while stationary, authority/replay equivalence, real static-body
collision, authored player composition, Courier animation selection, mouse projection, and focus
loss/regain. The bounded harness smoke moves the actual saved player scene on the saved ground sector.
