# M1-D1.1 production checks

9 October 2026. This task establishes the test-only production unit framework and one
canonical local/CI check without changing gameplay or saved scene composition. Its final reviewed
history is stacked directly on M1-A1.1, whose production Boot main removes the old export dependency
on a test fixture. Repository tools and configuration were edited directly because no Godot editor
or MCP editor was available.

## Pinned test framework

GUT v9.7.1 is vendored unchanged under `addons/gut/`. Its exact tag/commit, archive URL and
SHA-256 are recorded in `addons/gut/PROVENANCE.md`; the bundled MIT `LICENSE.md` is retained.
The project uses `addons/gut/gut_cmdln.gd` headlessly. GUT is not an autoload and its editor
plugin is absent from `project.godot`'s enabled plugin list.

`.gutconfig.json` discovers only `tests/unit/` recursively. The passing smoke lives under that
default tree. An intentional failure lives separately under `tests/diagnostic/gut_failure/`.
The canonical runner invokes it with the default config disabled and accepts the diagnostic
check only when GUT returns nonzero and prints the expected failure marker.

`tools/script_checks.py` and the older resource helper exclude only the exact GUT and MCP vendor
paths from project-owned script discovery. Project-owned production, fixture, unit and diagnostic
scripts remain formatted, linted and explicitly compiled. The compile mirror now retains the
otherwise-hidden `.gutconfig.json` while still removing development editor/MCP startup.

## Canonical check and CI

`python tools/production_checks.py --output <fresh-external-directory>` verifies exact engine
`4.8.dev7.official.c971f93e7`, then runs:

1. owned-script formatting, zero-warning lint and explicit all-owned compilation;
2. complete Python discovery with `tools/*test*.py`;
3. a clean headless import of the isolated test mirror;
4. the default GUT suite with JUnit output; and
5. the isolated intentional-failure detection.

Every child is bounded and writes logs plus `summary.json` outside the checkout. A repeatable
`--gut-dir tests/unit/<owner>` option selects one unit subtree while retaining all other canonical
layers. The GitHub remote is explicit, so `.github/workflows/production-checks.yml` runs this same
entrypoint on Windows and
Linux using the exact `mise.toml` pins and retains logs. Windows is executed locally here; Linux
execution remains deferred to the workflow/a Linux machine and is not inferred from Windows.

All four export presets exclude `addons/gut/**` and `tests/**` in addition to the existing MCP
boundary. `tools/s08_x/inspect_exports.py` rejects either test-only prefix and derives required
package members from the configured `run/main_scene` plus recursively referenced text resources,
rather than hard-coding an S06 fixture. Focused Python tests cover recursive discovery, a missing
dependency and forbidden synthetic package paths.

The first proof used a scratch main because the then-current main directly instanced an excluded
S06 test fixture. Review correctly blocked that tree. The final branch is instead stacked on reviewed
M1-A1.1 commit `d986213`, where `project.godot` selects `res://scenes/boot/boot.tscn` and all Boot
scene/script dependencies are production paths.

On committed stacked task HEAD `89e146d`, Windows debug/release and Linux debug/release exports all
exited zero without substituting project files. Inspection passed all four 596-entry packages. It
found the Boot scene plus six recursive scene/script dependencies, no missing dependency, and zero
`tests/` or `addons/gut/` entries. The earlier 465-entry scratch receipts remain historical evidence
only and no longer stand in for acceptance.

The export processes retained the pre-existing MCP Godot-4.8 compatibility warning. It comes from
the development editor plugin before export and is not a package leak; the package receipt found no
MCP, GUT or test content. No native Linux runtime launch is claimed by this cross-export and package
inspection.
