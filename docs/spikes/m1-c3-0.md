# M1-C3.0 — pedestrian core behavior and budget

10 October 2026. This is the production host-only pedestrian behavior core from
M1-C3.0. It consumes an injected navigation interface and does not load archived
prototype fixtures or create bodies, scenes, health, replication, or presentation.
M1-C3.2 later binds it to RT-07/CityData navigation, ActorMotion and the delivered
Off-Shift Worker scene.

## Ownership and API

`PedestrianCore` owns compact parallel typed state for at most 64 stable pedestrian
identities. A caller supplies current authoritative XZ positions with `sync_position()`;
the core never writes a body pose. `step()` runs every 60 Hz host tick. Route/threat
choices are staggered over six phases, so each identity decides at 10 Hz while every
identity emits held motion intent at 60 Hz. Threat publication accepts the typed
`GUNFIRE`, `BLAST`, and `VEHICLE` kinds and retains the kind in each record. Live
publication and per-decision scanning share the same cap of eight records, so every
accepted live threat is considered on an identity's next decision. Every eligible
threat identity receives an exact receipt in that phase; the latest published eligible
identity is selected deterministically for steering. Receipt maps retain only currently
live threat IDs and are pruned with the owning record, so each map is structurally
bounded by the live cap. Publication expires records at its supplied host tick before
applying the live cap. Lifetime is capped at five seconds.

`PopulationNavigation` is the injected boundary for finite nodes, sidewalk neighbors,
marked crossing IDs and crossing conflict sets. Production code contains no interim
Brackett road layout. Tests implement an independent 8x8 synthetic block grid with
eight marked crossings; RT-07 supplies the real load-time graph later.

`PopulationSpatialGrid` is one reusable fixed-cell neighbor index. It supplies bounded
local separation without introducing NavigationAgent/RVO or copying S10's dictionary-
heavy fixture. `PedestrianStateStore` keeps identity, node, state, decision, sequence,
flee, aim and crossing fields in typed packed arrays.

`CrossingReservations` owns the finite crossing policy:

- four simultaneous pedestrians per marked crossing by default;
- 16 queued identities per crossing;
- six seconds maximum queued wait;
- five seconds maximum active overlap/occupancy;
- no duplicate or cross-crossing claim by one identity;
- configured conflict sets block simultaneous grants; and
- `should_ai_traffic_yield(crossing_id)` exposes active crossing/conflict state.

The query is deliberately named and documented for AI traffic. Player-driven cars do
not call it and never auto-yield (owner decision 32). Expiry removes stale claims and
promotes compatible queue heads; tests also use a stricter three-second wait to exercise
behavior recovery before the recorded six-second production bound.

The core has wander, queued-crossing, crossing and flee states. Graph choices are
deterministic per identity/decision. Flee picks the legal neighboring link farthest
from the observed threat, while marked links still require a reservation. Flow lanes
and spatial separation are steering inputs, not collision or damage verdicts.

## Foot-command seam

M1-A2.1 owns the shared `FootCommand` type. After its integration, the isolated
`PedestrianCore.to_foot_command()` adapter now returns that production type directly
with sequence, client tick, move, aim yaw, fire-held and alt-held fields. Movement is
world-relative and canonicalized to length at most one; yaw is finite radians; AI fire
and alt intent are false. The adapter does not bind or move an `ActorMotion` body.
Focused tests assert the concrete type, production validation, ranges and monotonic
sequence.

## Behavior acceptance

The metric definitions deliberately follow S10:

- sampled overlap pairs use actual synthetic motion positions once per second;
- continuous overlap duration checks every 60 Hz motion tick;
- a stuck identity moves less than 0.25 m over any four-second window;
- crossing wait is the oldest queue age and queue length is the peak finite queue;
- active reservation overlap is the longest occupancy; and
- flee reaction is host ticks from publication to that exact threat identity's receipt,
  including multiple eligible identities received during one decision phase.

The accepted thresholds are:

| Metric | Threshold |
| --- | ---: |
| Maximum sampled overlap pairs | 24 |
| Maximum continuous overlap | 180 ticks / 3.0 s |
| Stuck identities per run | 26 of 64 |
| Crossing wait / queue age | 360 ticks / 6.0 s |
| Crossing queue length | 16 |
| Active reservation overlap | 300 ticks / 5.0 s |
| Flee reaction | 5 ticks / 83.33 ms |

Seeds 101/202/303 each ran a 7,200-tick (two-minute) normal case and global flee case
on the 8x8 graph. Normal threats use the seeded generator; flee runs rotate the initial
identity-to-node assignment by a seed-derived offset while retaining global threat
coverage. Synthetic motion applied the emitted command at the planned 5 m/s
ActorMotion speed and fed the resulting position back through the public API.
All six runs passed. Exact results are retained in
[`m1-c3-0-evidence/behavior-results.json`](m1-c3-0-evidence/behavior-results.json).

| Scenario | Sampled overlap max | Continuous overlap max | Stuck range | Queue length / age max | Flee max |
| --- | ---: | ---: | ---: | ---: | ---: |
| Normal | 0 | 11 ticks | 6–26 | 2 / 180 ticks | 5 ticks |
| Flee | 0–1 | 10–13 ticks | 13–21 | 0 / 0 ticks | 5 ticks |

S10's accepted ten-minute fixture reported sampled overlap maxima of 58–76 in normal
runs and 209 in flee runs, with 28–43 and 64 stuck identities respectively. C3.0's
shorter production-core runs therefore pass explicit thresholds that reject those S10
results. The comparison does not claim equivalent duration, final island collision or
crowd look. C3.2 must repeat these thresholds in Brackett with selective collision
queries, real bodies, RT-07 routes and real threats before scaling is accepted.

## Timing and limitations

Decision 22 makes subsystem timings reporting-only under the soft total host budget.
This lane intentionally records no timing gate: M1-D3.0 owns production tick brackets,
named-machine percentiles and the integrated total. Accelerated GUT duration is not a
frame-time measurement.

The Godot editor was unavailable. These pure logic scripts and tests were edited
directly, imported with the pinned engine to generate `.uid` sidecars, and compiled by
the production checks. No saved scene hierarchy was authored or changed. Full-project
import reports the known development MCP version warning; focused compiler mirrors and
GUT reject script diagnostics.
