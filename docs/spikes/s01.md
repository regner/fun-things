# S01 — Blender → GLB → Godot roundtrip

7 October 2026. Codex owns source authoring, integration, resource validation and
technical review. **Accepted for this bounded fixture workflow**, with the limits
below. This is a technical proof, not production art, person-rig acceptance,
Steam/Deck compatibility or an engine upgrade. Proposed cap: 1–2 focused days;
this experiment stayed within one implementation session.

Question: can explicit Blender exports remain linked through repeated and inherited
Godot wrappers without losing authored placement, identities or appearance tuning?
Use explicit GLB rather than direct `.blend` import so Godot has no authoring-tool
runtime dependency. The accepted Petrol & Coral palette and city axes inform the
fixtures; the six-block layout, actual camera/actor envelopes and production art
remain [separate briefs](../world-layout.md).

Blender is selected for this workflow through the version assertion in
`tools/s01/export.py`; `mise.toml`'s engine and gdstyle pins are unchanged. Blender
sources use Metric, unit scale 1, 30 fps, +Z up/+Y front. Rotation and scale are
applied before binding; all object scales are positive unit scale. Mesh bevels
(0.025 m, two segments), smooth normals and triangulation are applied in Blender.
The skin retains only its armature modifier. No procedural mesh is made in Godot.

[Export preset](../../tools/s01/export_settings.json) records supplied operator
settings. `collection=export_<asset_id>` is assigned explicitly; selection and
visibility do not choose membership. Each collection's exact membership is checked
before export. The collection is the export scope; GLB contains several object
roots and Godot's synthetic model root stays identity. Cameras/lights/extras and
morphs are excluded; UVs/normals/skins included; tangents not exported. All static
modifiers are already baked, so `export_apply=false` also preserves skinning.
GLB buffers are internal, but there are **no embedded images/textures**, extensions,
Draco or meshopt compression. Shader procedural baking, normal maps and LODs are
not applicable to this tiny proof.

Rig export uses ACTIONS with ACTION merge, one intended slotted action per clip,
no scene-range limitation, forced sampling every frame, optimization disabled.
Muted named NLA tracks retain action/slot associations in the source. There are
exactly `idle`, `walk`, `run`, `death`; no accidental rest/test action. Actions cover
frames 1–31 at 30 fps. Godot imports each as **1.0333333 s**, including its terminal
sample. Do not infer one second from Blender's endpoint subtraction. All animation
is in place, on hand rotation; simulation/placement roots are not tracks.

Committed `.glb.import` files are the exact engine-saved importer settings, including
UID material paths plus fallback paths and engine-generated animation slice fields.
Scene importer version is 1, naming version 2, root scale 1 with apply_root_scale
true, named skins, animation fps 30, trimming false, immutable-track removal false,
rest-as-RESET false. Idle/walk/run use `Animation.LOOP_LINEAR`; death LOOP_NONE.
LOD generation is disabled for these tiny fixtures only; shadow meshes/tangents
remain enabled and compression is not globally disabled. Material `body_paint`
remaps to `s01_petrol.tres`; variant `body_material` points to `s01_coral.tres`.

Palette is an explicit 8×8 RGBA PNG with source/runtime bytes equal and cube UVs.
It is used as albedo color data; opaque StandardMaterial3D, roughness 0.8, linear
mipmapped filtering, repeat enabled. Engine-saved texture settings use VRAM
compression mode 2, S3TC/BPTC cache on this platform, high quality false, mipmaps
true/no limit, no normal-map inversion, no premultiplied alpha or emission. This is
a remap/dependency fixture, not a calibrated production palette or texture budget.

## Experiments and observed outcomes

Before editing: read AGENTS, asset/scene contracts, accepted art/city briefs and
existing tooling. No owned assets/checks existed; no editor was connected. A
sandboxed GUI launch lacked X11 access; a headless launch lacked local sockets.
The installed pinned editor was then launched with display/socket access, normal
registry and `GODOT_MCP_EDITOR_PORT=6550`. Its initial scene state was `NO_SCENE`;
there was no unsaved scene to discard. No engine or vendor addon was changed.

MCP created nodes, set resources/properties/scripts and saved all scene batches.
On-demand tools were discoverable but absent from this session's callable surface.
Additionally, toolkit scene instantiation rejects `.glb` paths. The MCP-written
`tools/s01/editor_probe.gd`, used by `editor_harness.tscn`, bridges the toolkit's
scene/resource commands and instantiates linked GLBs through PackedScene in the
editor, setting only the instance root's owner. It copies no vertices. This small
bridge depends on toolkit 1.0.3 internal handlers and is not a production API.

### Rejected direct imported-child override

The first inherited variant overrode `Visuals/Model/Body.material_override` with
editable imported children. After re-export/reopen its saved imported Body
`unique_id` changed from **2010825547 to 789504035**, despite unchanged node path,
material override, wrapper identities and placement. This route fails the identity
gate on this pin; do not use it for accepted variants. Original before/after
snapshots are retained, rather than claiming they were unchanged.

Migrated the proof to an exported material parameter on the wrapper. Only the
wrapper root stores the inherited override, and its existing UID/root identity is
preserved. Presentation applies that authored material after model entry; it
neither constructs nodes nor modifies placement. Retested with an actual second
source geometry change: all 13 persisted files are now unchanged. Direct imported
child overrides remain an unresolved alternative; the accepted workflow does not
certify them. If production needs them, investigate engine/import support in a
separate bounded task; engine-pin changes remain deferred.

```sh

mise run gdscript:check

```

Mise trust-state writing is restricted in this environment, so equivalent commands
were executed with `GODOT_BIN`/`GDSTYLE_BIN` pointing to the installed mise pins:
`python tools/check.py style|scripts|resources`, `python tools/s01/reexport.py`,
`python tools/s01/clean_import.py`. These tools retain logs under ignored `builds/`,
use bounded subprocess deadlines and private temporary user/cache directories,
and stop only children they launch. Compilation explicitly checks all three owned
scripts, including editor helper/unused entrypoints; import is a separate check.
Style uses pinned gdstyle with zero allowed warnings; purpose comments, two-empty-line
function separation and authored exports were manually reviewed. No formatter fix
wrapper or network runner was added.

After editing a source, use `python tools/s01/reexport.py --install`; it validates
both scratch outputs before replacing GLBs and preserves import sidecars. Open
editor_harness, call refresh, then close/reopen affected saved wrappers/variant/
roundtrip, save each and rerun resource checks. The bootstrap source creator is
historical/rebuild tooling, not the normal re-export path: committed `.blend` files
own authoring. Routine source changes must update exports and handoff evidence.

## Diagnostics and limitations

Full-project headless clean import was also attempted **and is not clean**: the
first pass reports GodotSteam's missing `get_godotsteam_version` call and null bottom
panel control; the second reports editor/native UI RID/ObjectDB/resource leaks.
Those logs are retained as failures, with exit status 0 explicitly insufficient.
The asset-profile proof excludes those plugins in its temporary copy and suppresses
no diagnostics. Steam/plugin compatibility belongs to S03/S08, not this asset proof.

Existing-editor MCP reload/import attempts emitted progress-dialog/message-queue
errors (`Do not use progress dialog ...`, followed by `!tasks.has(p_task)`). The
engine still saved and reopened the measured resources; identities/outcomes were
checked independently. The helper now uses the toolkit's safe scene-close path
followed by scene_open. Logs retain the diagnostics; do not equate an MCP success
response to error-free editor internals. Transient parse errors while adapting the
helper to exact pinned API signatures were corrected; final explicit compilation
and script_check pass. Toolkit null-return hints also incorrectly
suggested non-@tool code for successful void engine/helper calls; all saved results
were checked. Blender reports missing optional MeshOptimizer on export; compression
is disabled and validated GLBs have no compression extensions. No vendor fix or
engine compatibility claim is included.

Unproven production cases: full humanoid/shared-outfit rig, retargeting, useful
walking/death art, normal/ORM maps, alpha effects, LODs, extensive material slots,
source libraries, actual collision/movement/vehicle clearance, world sector seams,
export packaging/source exclusions, performance, Deck controls/hardware, and
real-process multiplayer. They remain with their existing downstream tasks. S01
accepts only the explicit export, linked wrapper, wrapper-level variant and focused
resource workflow demonstrated here. P0-03 remains open for S03's two-process runner;
no downstream gameplay task was begun.
