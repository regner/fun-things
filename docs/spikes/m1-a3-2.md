# M1-A3.2 — production audio buses and voice policy

Status: implemented production foundation, 10 October 2026.

## Production contract

`default_bus_layout.tres` installs the accepted S14 routing set at neutral default
levels while settings remain deferred to M1-D5: Master, Music, SFX, Engines,
Weapons, Explosions, UI and Ambience. Engines, Weapons, Explosions and UI route
through SFX; Ambience routes through Music. Master has the S14 safety limiter with
a -1 dB ceiling. This is a safety margin, not final-asset gain staging.

`AudioVoiceService` is the sole voice-selection owner for the S14-measured spatial
categories: eight engines, six weapons and eight explosions. It ranks desired
voices by explicit presentation importance, then listener distance, then newer
request significance. A better request steals the lowest-ranked selected voice.
Displaced continuous engine states remain waiting and can be promoted when another
engine stops. Rejected or displaced weapon/explosion one-shots are dropped rather
than replayed late. Drop/steal counters are presentation telemetry only and never
affect gameplay or visual events.

`StateAudioEmitter3D` consumes an externally decided active state, stream and pitch.
It requires explicit injection of the service, routes to the selected category bus,
and owns only its saved `AudioStreamPlayer3D`. Emitter despawn releases its request;
service teardown revokes and stops every managed player before clearing references.
It does not read input, resolve damage, deduplicate network events or decide a
simulation outcome.

The reusable saved scenes are under `scenes/audio/`. The saved GUT composition,
reproducible mathematical test tone and generator are under `tests/unit/audio/` and
are excluded from exports. They are technical placeholders, not production sounds.
The Godot MCP editor was unavailable for this worktree, so scenes were authored as
text and then loaded/resaved with the pinned headless editor to assign stable UIDs.
