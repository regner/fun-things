# S08-X — real-project desktop export smoke

8 October 2026; Windows execution against pinned Godot
`4.8.dev7.official.c971f93e7`. This closes the bounded G4 implementation and
Windows smoke. Linux export packaging passed on Windows; Linux execution remains a
checklist for a Linux desktop, as owner decision 10 permits.

## Real project entrypoint and presets

[`project.godot`](../../project.godot) now selects the saved
[`run/main_scene.tscn`](../../run/main_scene.tscn). The scene instances the accepted
saved [`S06 intersection`](../../tests/fixtures/s06/intersection.tscn); it does not
rebuild that hierarchy in code. The editor and MCP scene tools were unavailable, so
this minimal wrapper was authored as text, imported with the pinned engine, and its
generated script UID was committed.

[`export_presets.cfg`](../../export_presets.cfg) defines Windows Debug, Windows
Release, Linux Debug and Linux Release x86-64 presets. Every preset uses an external
PCK, no encryption, and the real project. The debug/release distinction is selected
by the matching `--export-debug`/`--export-release` command; separate names make the
four intended outputs explicit.

The exported-only observer in [`main_scene.gd`](../../run/main_scene.gd) checks that
the S06 instance loaded and the MCP autoload setting/node and GodotSteam
class/singleton are absent. `--s08-x-export-smoke` caps at 60 FPS, runs 30 frames,
prints a receipt, and exits; ordinary launches do not auto-exit.

## Provisional M1 addon boundary — owner review still required

Owner decision on removing GodotSteam is still pending. The implemented default is
the audit brief's conservative option: **keep both vendor addons in the repository
for development, but exclude all `addons/godotsteam/*` from every current ENet-only
M1 export**. The same presets exclude `addons/godot_mcp_toolkit/*` and `.mcp.json`.
The loaded MCP editor export plugin temporarily removes its autoload setting while
baking; the preset excludes its files as a second boundary.

Package inspection found neither addon, `.mcp.json`, nor a GodotSteam shared library
in any of the four output folders/PCKs. The Windows release observer independently
reported no MCP node/setting and no Steam class/singleton. This proves the current
export boundary, not future Steam adapter compatibility.

If the owner later selects removal, do it as a separate coordinated change: disable
the GodotSteam editor plugin, remove `addons/godotsteam/`, update any project/editor
references, clean-import, compile, export, and re-run package/runtime checks. Do not
silently turn this provisional exclusion into an integration decision.

## Reproduction

With the pinned engine on `PATH`, installed matching templates, and a fresh external
output root:

```sh
OUT=C:/tmp/ft/lanes/s08-x
mkdir -p "$OUT"/{windows-debug,windows-release,linux-debug,linux-release}
timeout 300s godot --headless --path . --export-debug \
  "Windows Debug" "$OUT/windows-debug/FunThingsDebug.exe"
timeout 300s godot --headless --path . --export-release \
  "Windows Release" "$OUT/windows-release/FunThings.exe"
timeout 300s godot --headless --path . --export-debug \
  "Linux Debug" "$OUT/linux-debug/FunThingsDebug.x86_64"
timeout 300s godot --headless --path . --export-release \
  "Linux Release" "$OUT/linux-release/FunThings.x86_64"
timeout 120s python tools/s08_x/inspect_exports.py \
  --root "$OUT" --output "$OUT/package-inspection.json"
```

Before the Windows smoke, `tasklist` showed no `steam.exe` and no other
Godot/exported-game process. This launch was windowed, D3D12 Forward+, 1280x800,
capped to 60 from process startup and exited 0 after 30 frames:

```sh
cd "$OUT/windows-release"
timeout 60s ./FunThings.exe --position 50,50 --resolution 1280x800 --max-fps 60 \
  --log-file "$OUT/logs/windows-smoke.engine.log" -- --s08-x-export-smoke
```

The retained [evidence catalogue](s08-x-evidence/README.md) maps hashes and logs.
All four final post-rebase export commands exited 0 and inspection passed. Exports
and the Windows smoke each began with zero other Godot/game processes and are
labelled **quiet**; this remains functional, not performance, evidence. The runtime
log has zero warnings/errors. The headless editor export
processes emitted the existing MCP 4.8 compatibility warning and teardown
RID/ObjectDB diagnostics; those did not occur in the exported runtime and remain a
tooling follow-up.

## Linux desktop launch checklist

Linux execution was not claimed on Windows. On a Linux desktop:

1. Verify the exact engine version, template archive/version/member hashes above,
   and the transferred Linux export hashes in `package-inspection.json`.
2. Confirm Steam is not running using the desktop's normal read-only process view;
   do not stop a shared process. Record the Godot process count and label contention.
3. From the complete release folder, run
   `timeout 60s ./FunThings.x86_64 --position 50,50 --resolution 1280x800 --max-fps 60 --rendering-driver vulkan -- --s08-x-export-smoke`.
4. Observe the 1280x800 window and focus, and retain stdout/stderr plus `--log-file`.
   Require both `S08-X` events with `ok:true`, 30 frames, max FPS 60, exit 0, and no
   warning/error diagnostics.
5. Re-run `inspect_exports.py` over all four folders if they were rebuilt on Linux.

This checklist does not claim Steam, Deck, input/focus switching, performance, or
production acceptance.
