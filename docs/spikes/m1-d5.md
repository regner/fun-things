# M1-D5 — LocalSettings and settings UI

Status: core implemented; Boot wiring deferred pending M1-A2.5 integration, 10 October 2026.

## Production contract

`LocalSettings` is the sole device-local writer for schema-versioned presentation settings. It
persists Master, Music and SFX linear levels and mute values at the canonical
`user://settings.cfg`, applies only those A3.2 buses, and leaves category routing and duck effects
untouched. It also owns windowed/fullscreen, VSync and a mandatory 30/60 FPS cap; disabling VSync
never creates an uncapped mode. Defaults are neutral gain 1.0 on all three buses, unmuted, windowed,
VSync on and 60 FPS. No migration is needed because the earlier noncanonical path never shipped.

Loading validates every known field and exact type, clamps finite levels, and treats malformed syntax,
schema or known-value types as one corrupt transaction. A corrupt file is renamed to a unique backup
before safe defaults or a validated `.previous` generation are applied. The settings screen presents
the resulting nonfatal recovery warning visibly. Saving writes the complete schema to a sibling
`.tmp` file, preserves the prior file as `.previous`, promotes the temporary file by rename, rolls
back on a failed promotion, and propagates preservation, promotion, rollback and cleanup failures.
On restart, a missing destination restores and validates `.previous`; a valid destination is
established before `.previous` is deleted; and an uncommitted `.tmp` is never promoted. Callers
receive the exact save error and the UI stays open with feedback when persistence fails.

The saved `settings_menu.tscn` previews changes through the injected owner, restores its opening
snapshot on Back/Escape, and persists only through Save & back. Its sliders, checks, option buttons
and actions use ordinary Control focus for keyboard/mouse navigation. `MainMenu` exposes a Settings
button as navigation intent; it does not discover Boot or own settings state.

This production implementation ports S14's three top-level audio preferences, not its fixture code.
The production defaults and storage follow the canonical contract and decision 28 rather than S14's
prototype tuning. It adds corrupt backup and warning, interruption-safe replacement/failure paths,
display preferences and an authored reusable screen. No gameplay or replicated state is read or
written.

## Validation and composition note

GUT coverage under `tests/unit/settings/` checks canonical defaults/path, validation/clamping,
corrupt backup and visible warning, invalid-type recovery, atomic replacement, every interrupted
`.tmp`/`.previous` restart state, write failure cleanup, live bus preview, A3.2 routing preservation,
settings focus/cancel/failure feedback and MainMenu navigation intent.
Canonical results are retained outside the worktree under
`C:/tmp/ft/lanes/m1-d5/production-checks/`.

Godot MCP editor tools were unavailable for this worktree. The settings scene was authored directly,
then loaded, instantiated, packed and resaved with pinned Godot
`4.8.dev7.official.c971f93e7`; script UID sidecars were generated by a bounded pinned headless import.

## Deferred Boot wiring

M1-A2.5 owns `scenes/boot/boot.tscn` and `scripts/boot/boot.gd` concurrently and was not integrated
when this core was reviewed. After A2.5 lands, rebase this lane and add one small wiring commit:

1. save one process-lifetime `LocalSettings` node under Boot and one `SettingsMenu` instance in View;
2. have Boot load LocalSettings, inject it through `SettingsMenu.configure()`, and coordinate the
   existing `MainMenu.settings_requested` / `SettingsMenu.closed` signals; and
3. add a Boot-level GUT test proving the saved screen is reachable, returns to the menu and preserves
   settings while Boot switches views.

Until that commit lands, the production service and screen are independently usable and tested, but
the saved Boot entrypoint does not yet expose them at runtime.
