## Fixture and boundary

[Saved fixture](../../prototypes/s03/tests/fixtures/s03/boot.tscn):

```text
/root/Boot
├── Session                    S03Session: provider/mapping/admission/cleanup
└── View/Match                 S03Match: provisional lives and held bindings
    ├── Replication            S03Replication: baseline, journal, handoff, movement
    ├── RuntimeEntities        saved marker scenes, configured off-tree
    └── CityRoot               empty; saved local rig is instantiated after hydration
```

The saved rig contains Input, CameraAnchor/Camera3D and UI placeholders. Each
process has one local rig, regardless of the number of replicated players.
Markers are nonrendering Node3Ds. There are no Blender fixtures, generated meshes,
colliders, movement controller, weapons, seats, HUD or authored city in this proof.

Scripts remain under `prototypes/s03/tests/fixtures/s03/`, with explicit injection and the proposed
production-facing responsibilities. Boot coordinates children; native objects stay
in the provider/service boundary. This is a proof to deliberately replace or
productionize at P0-GATE/M1, not a production session service. The narrow calls
are `select_provider`, `host(port)`, `join(adapter_target)`, `cancel(operation)`,
`leave`, `request_resync`, Match preparation/application and `submit_held`.
The full typed request/result/view/platform APIs in the design remain proposals.

All scripts and scenes were authored with Godot MCP Toolkit tools. No scene was
open initially. The editor connector failed authentication after editor startup;
an authenticated local WebSocket client used the same toolkit script/scene tools
against this worktree's registry entry. Boot was saved/reopened and the fixed tree
inspected; all seven scripts also passed toolkit `script.check`. Saved scene UIDs,
node identities and generated script `.uid` files are retained. This is not S01's
inherited-asset/source roundtrip validation.

resolve them. In this sandbox Mise's trust-state symlink was read-only, so checks
used the installed pinned executables explicitly. Engine pin and Steam integration

Each child has separate `host/user` or `client/user` XDG data/config/cache and
`host/logs` or `client/logs` stdout/engine files. The parent starts the client only
after structured host readiness; records must include successful results and
process exits. Ports are configurable and distinct. Per-case waits are 8 seconds,
service/hydration waits 15 seconds, native close 20 ms, and the two-process deadline
defaults to 25 seconds. Setup has a 10-second version check, 30-second import waits
and a 120-second compiler budget with at most 30 seconds per explicit invocation.
Timeouts, engine/script errors or warnings, early exit and incomplete fault schedules
fail the run. Logs survive failure. Cleanup signals only stored Popen children,
with bounded terminate/kill waits; it never scans or kills by process name.
SIGINT/SIGTERM use that cleanup path. Forced destruction of the runner itself
(for example SIGKILL) cannot execute Python cleanup.

Script checks use a **fresh dependency mirror**, retaining source project settings,
autoload declarations, dependencies and `.gdignore`, while disabling editor plugins
for compiler setup. Import discovers classes; every owned script then receives its
own `--check-only --script` invocation even if setup reported errors. Hidden and

Blender provenance or source-link acceptance is inferred from compiler import.
Pinned formatting/lint pass; comment attachment, two blank lines between functions
and logical spacing were reviewed manually. A preserving formatter wrapper remains

## Alternatives, limitations and resulting work

One process with two MultiplayerAPIs would not prove separate-process lifetime.
Dirty-only subset publication cannot recover a lost unchanged subset. A global
packet watermark cannot acknowledge omitted entities. Plain unreliable delivery
with per-entity freshness, full snapshots or one ordered channel per independent
stream are alternatives; the minimum proof retains the proposed ordered channel
and requires repeated bounded refresh. Godot documents the
[ordered-stream discard behavior](https://docs.godotengine.org/en/latest/tutorials/networking/high_level_multiplayer.html#remote-procedure-calls);
the actual pinned-engine proxy experiment is the evidence here.

This proves only the scoped session contract on local Linux. It does not implement
or accept full/incompatible/unreachable/slow joins, general callback correlation
for an uncorrelated SDK, cleanup of a hung native provider, baseline duplicate/
overflow handling at M1 size, reset, seats/equipment, collision fences/tombstones,
future-state buffering, all malformed wire shapes, abuse disconnect policy, flood/
host-stall behavior, capacity, sustained bandwidth or the brief's latency/jitter/
loss profiles. The fake's callbacks carry actual operation/epoch correlation and
retain cleanup-only ownership after cancellation; they do not certify Steam.
Journal content is one deterministic health change, not a general mutation journal.
Motion is a fake sample with dependencies, not an actor controller or visual response.

The canonical architecture/API/multiplayer guides now retain the split-subset
refresh decision and separate proven minimum behavior from production acceptance.
Production codecs, batching, repeated-abuse policy and capacity/recovery acceptance
remain M1-A/D work. S01 owns Blender fixtures and asset/resource/source checks;
S03-R/S04 own responsiveness and gameplay bodies; S03-S owns actual Steam; S08
owns Deck/export compatibility and any engine-pin decision. No Steam integration,
Deck compatibility or engine-pin change is claimed. P0-03 completion is limited to
its minimum foundation tooling acceptance, combining S01 and S03.
