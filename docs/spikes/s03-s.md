## Boundary and initialization requirements

[Common session/API contracts](../api-contracts.md#transport-and-platform-adapters)
still own admission and four logical streams. SteamPlatform owns lobbies/invites;
SteamTransport owns the actual gameplay peer. SessionService attaches it only after
endpoints exist and maps `(active operation, native peer ID)` to fresh ParticipantId
after handshake. SteamID/lobby membership grants no gameplay admission.

Peer source supplies `get_steam_id_for_peer_id`/`get_peer_id_for_steam_id`; host peer
is 1 and clients generate peer IDs. The adapter must authenticate native connection
identity and retire mappings on close, preserving SessionId/revisions and host-loss
termination. Lobby ownership changes cannot migrate the authoritative match.
Convenience lobby helpers connect other members too; explicitly evaluate the listen
server path instead of assuming their topology/ownership satisfies the contract.

[Steam source](https://codeberg.org/godotsteam/godotsteam/src/commit/532740f3f9c6a826c68914db81af9de1e32d5dc3/godotsteam.cpp),
`steamInitEx`, lines 518–550, accepts AppID/embed_callbacks and returns status/verbal
diagnostics. `createLobby` retains one call-result object but exposes no call handle;
`joinLobby` discards the native request handle and `lobby_joined` reports a lobby ID.
These signatures do not prove safe cancel/retry correlation. Serialize uncorrelated
operations and prove drain/cleanup-only ownership before reuse, or report unavailable
until safe restart. Do not copy ENet's 20 ms fixture close delay as a Steam guarantee.

[Valve initialization guidance](https://partner.steamgames.com/doc/sdk/api) requires
a running client in the correct OS user context, app identification and entitlement,
with usable app/default-package setup. Ship the matching Steam API redistributable;
development `steam_appid.txt` is not a depot artifact. Preserve optional initialization
and verify offline/ENet packaging without Steam separately. No initialization was
attempted here; AppID 5294580's live state remains unknown.

Registered diagnostics include `getConnectionInfo`, `getDetailedConnectionStatus`,
`getConnectionRealTimeStatus`, `initRelayNetworkAccess` and `getRelayNetworkStatus`.
`get_peer(peer_id).get_connection_handle()` exposes the connection for diagnostics;
source connection info includes remote identity, relay POP, flags/state/end reason.
[Relay availability](https://partner.steamgames.com/doc/api/ISteamNetworkingUtils)
alone cannot prove a connection used SDR. When external proof resumes, retain
per-connection route/status/traffic observations from both ends, not only lobby or
relay-initialization success. No such diagnostics were exercised in this pass.
