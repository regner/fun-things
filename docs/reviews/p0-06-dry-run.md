# Independent GDScript review

Scope: the replacement `actor.gd`, `match.gd`, `hud.gd`, and both saved scenes in this fixture, against `CONTRACT.md` and the canonical repository guidance. All behavioral findings below are static inferences from those production paths; no gameplay or network execution was performed. Paths and line numbers are fixture-relative.

1. **P1 — RPC callers can select another actor and supply authoritative damage.** `match.gd:19–23`, also `match.gd:27–31`. Both `any_peer` endpoints use `claimed_peer_id` to select an actor without comparing it to `multiplayer.get_remote_sender_id()` or checking authority/admission. A client can name another admitted actor; `submit_fire` then subtracts a client-selected integer from that actor's health. Negative damage heals, and large positive damage bypasses host combat rules. The command route likewise queues firing for another actor. Actor existence alone is not caller admission or ownership. **Minimal fix:** at the Match boundary require authoritative execution, derive the sender, validate its admission/control ownership, and resolve only its allowed actor. Accept fire intent and compute damage in Match rather than accepting a damage outcome. Give host-local intent an explicit path through equivalent validation. **Independent verification:** through the real RPC route, have admitted client A name B, an unadmitted peer name A, and A submit negative/excessive damage; none may mutate health or enqueue commands. A legitimate A fire request must produce exactly the host-defined outcome. An unsolicited client-side invocation must not mutate replica health.

2. **P1 — Prediction/replay applies damage and repeats presentation.** `actor.gd:44–48`, caller `actor.gd:52–54`; outcome `match.gd:35–36`. `_replaying` is ignored, and `simulate_command` checks neither authority nor `simulation_enabled`. Each replayed fire command calls `apply_shot` and emits `shot_presented`. Calling prediction on a disabled replica also reaches the Match mutation. Reconciliation therefore repeats damage accounting and effects instead of replaying only permitted simulation. **Minimal fix:** keep shared command simulation, but separate local simulated state from authoritative shot resolution and presentation; allow authoritative mutation only in the authority path, and suppress effects during replay. **Independent verification:** run a fire command once through normal simulation, record Match damage and presentation count, then replay that command repeatedly; both counts must remain unchanged. The prediction path for `simulation_enabled=false` must not alter authoritative outcomes, while ordinary authoritative firing still works once.

3. **P1 — Remote command ingestion and per-tick processing are unbounded.** `match.gd:28–31`, `actor.gd:30–31`, `actor.gd:39–40`. Any accepted batch is fully appended to an uncapped persistent queue, and one physics tick drains the entire backlog. A large batch or sustained batches force arbitrary host work and shot outcomes into one tick; disabled actors never drain their queues. Typed dictionaries do not provide batch, queue, rate, or work limits. **Minimal fix:** reject oversized/malformed requests before enqueueing; define local batch/rate/queue bounds and a fixed per-tick command budget with a documented overflow/supersession policy. Preserve authoritative tick pacing rather than treating backlog size as available simulation steps. **Independent verification:** submit at-limit and over-limit batches through the admitted production entry point, flood it, and inspect several paced ticks. Queue size, accepted request rate, and commands processed per tick must remain within independently specified limits; over-limit/invalid traffic must not partially enqueue or cause extra shot resolution. Also verify bounded behavior for a disabled actor. No particular numerical budgets are inferred from the repository's illustrative plans.

4. **P2 — Respawn emits completion before restoring health and held input.** `actor.gd:23–26`; observer `hud.gd:14–15`. `respawned.emit()` invokes the HUD synchronously while health is still the previous life value and `held_fire` is still true. A dead actor's HUD displays zero after respawn; initial ready observers see the initial zero. **Minimal fix:** finish authoritative health/input restoration before emitting completion. **Independent verification:** bind the actual HUD, set health to zero and held fire true, and call respawn. In a signal listener, independently assert full health and neutral input; after the call, the HUD must show full health without an extra refresh.

5. **P2 — Respawn leaves queued firing from the previous life active.** `actor.gd:23–26`, queue consumer `actor.gd:39–40`. Resetting `held_fire` does not remove pending commands. If firing is queued when respawn occurs, the next physics tick consumes the stale command, re-enables held fire, and applies a shot in the new life. This remains a bug after simply moving the signal to the end of respawn. **Minimal fix:** neutralize/clear pending input as part of the lifecycle transition before notification; reject commands from the old life at the admission boundary if they can arrive after that transition. **Independent verification:** queue fire through the production command path, respawn before the simulation tick, then advance a tick. No damage or shot effect may occur and input must stay neutral. A delayed old-life command must likewise be rejected, while new-life intent remains usable.

6. **P2 — Disabled replicas still perform the authoritative respawn in `_ready`.** `actor.gd:18–19`, mutation `actor.gd:23–26`; setup `match.gd:10–14`. Match correctly sets `simulation_enabled=false` before tree entry, but `_ready` ignores it and unconditionally resets health and emits a lifecycle event. The flag gates only physics processing. A replica therefore authors gameplay/lifecycle state at creation and would overwrite health hydrated before tree entry. **Minimal fix:** make replica ready initialization presentation-only and let Match own authoritative initial health/respawn; guard any authoritative transition against replica execution. **Independent verification:** instantiate an actor with simulation disabled and an independently chosen non-default health value before adding it to the tree. Tree entry must preserve that health and must not emit an authoritative respawn event. Authoritative creation must still initialize full health through its intended owner.

7. **P2 — Export rename drops existing Inspector tuning.** `actor.gd:9`; serialized caller `actor.tscn:7`. The old exported `movement_speed_mps` property is replaced by `walk_speed_mps`, while the saved prefab still contains `movement_speed_mps = 9.0`. The new export receives its 6.0 default instead of the authored 9.0 value. The fixture does not exercise movement, so the concrete regression here is lost configuration, not demonstrated walking behavior. **Minimal fix:** preserve the serialized export name, or perform an explicitly coordinated migration of all saved overrides and callers. **Independent verification:** load the existing prefab through Godot and assert the active movement tuning equals the authored 9.0; an editor save/reload roundtrip must retain that value and the intended property identity.

8. **P3 — Callback ordering differs from pinned style.** `actor.gd:35`. gdstyle 0.3.0 reports `_physics_process` after ordinary methods under `order/class-member-order`. **Minimal fix:** move the callback into the prescribed member order without changing its body, keeping its purpose comment attached. **Independent verification:** rerun the pinned read-only lint check; this warning should disappear without a behavior diff.
